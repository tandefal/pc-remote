# PC Remote

PC Remote — локальная система управления одним Windows 10/11 x64 компьютером с Android-смартфона (Android 10+). Для управления интернет, облако и пользовательские аккаунты не нужны: обнаружение выполняется через mDNS, первое сопряжение — одноразовым QR-кодом, последующие запросы — по уникальному токену устройства через HTTPS. Интернет используется только при ручной проверке и скачивании обновлений с GitHub Releases.

## Установка и обновление

Скачайте из [Releases](https://github.com/tandefal/pc-remote/releases) `PCRemote-Windows-X.Y.Z-Setup.exe` и `PCRemote-Android-X.Y.Z.apk`.

- Windows: закройте PC Remote через «Выход» в трее, запустите установщик, выберите папку и при необходимости ярлык на рабочем столе. Установка выполняется для текущего пользователя без прав администратора; .NET включён. Для защищённых системных папок выберите доступную пользователю папку. Удаление доступно через «Установленные приложения»; сохранённые привязки и настройки не удаляются.
- Android: при первом переходе с debug-сборки удалите её, установите release APK и заново выполните сопряжение. При последующих обновлениях удаление не требуется. Разрешите установку APK из используемого источника, если Android запросит.
- Windows: «Настройки → Проверить обновления»; Android: «Настройки → Проверить обновления», в том числе до сопряжения. Приложения запрашивают последний стабильный релиз, сравнивают версии, показывают описание и скачивают файл только после подтверждения. Проверяются размер и SHA-256 из GitHub API; Android дополнительно проверяет пакет, versionCode и совпадение сертификата подписи.
- Windows после скачивания закрывается и открывает установщик с текущей папкой установки. Android открывает системный установщик; если требуется разрешение, после его выдачи вернитесь и нажмите «Установить» снова. Автоматической установки без подтверждения нет.
- При отсутствии сети обновление можно повторить позднее; локальное управление продолжает работать. GitHub-токен в приложения не встраивается, поэтому релизы должны быть публичными. Предварительные и черновые релизы не используются. Windows-файлы пока не подписаны сертификатом Authenticode; Windows может показывать предупреждение о неизвестном издателе.

## Подготовка релиза

Используются существующие .NET SDK, JDK и Android SDK, а также Inno Setup 6. Компилятор ищется в стандартных папках и `artifacts/tools/inno/ISCC.exe`; другой путь можно передать через `-InnoCompiler`.

```powershell
# Только первый раз: создать постоянный ключ Android и собрать первый релиз.
.\packaging\Build-Release.ps1 -Version 1.0.0 -VersionCode 1 -InitializeSigningKey
# Следующие выпуски: увеличивать обе версии, использовать прежний ключ.
.\packaging\Build-Release.ps1 -Version 1.0.1 -VersionCode 2
```

Скрипт собирает автономную Windows x64 публикацию, установщик, подписанный release APK, выполняет Android lint и создаёт SHA-256 файл. Результаты находятся в `artifacts/release/`. Для версии `X.Y.Z` создайте GitHub Release с тегом `vX.Y.Z` на коммите соответствующих исходников, прикрепите `PCRemote-Windows-X.Y.Z-Setup.exe`, `PCRemote-Android-X.Y.Z.apk` и `SHA256SUMS-X.Y.Z.txt`, добавьте описание и опубликуйте как последний стабильный релиз. Автоматически создаваемые GitHub архивы исходников не заменяют эти файлы. Имена файлов должны совпадать с версией тега. Каждый выпуск должен содержать обе платформы.

Ключ Android хранится в игнорируемом `artifacts/signing/pcremote-release.jks`, пароль — в `credentials.xml`, зашифрованном Windows DPAPI. Не коммитьте и не прикрепляйте эти файлы к релизу. Сделайте защищённую резервную копию ключа **и пароля**: XML расшифровывается только исходным пользователем на исходной установке Windows; одного копирования XML на другой ПК недостаточно. До переустановки Windows перенесите пароль из сохранённого PSCredential в менеджер паролей. Потеря ключа или пароля лишит возможности выпускать совместимые обновления. Скрипт запрещает перезапись существующего ключа.

## Требования

- Windows 10/11 x64 и .NET 8 SDK для сборки WPF-приложения.
- Android Studio, JDK 17 и Android SDK 36 для Android-приложения.
- Телефон и компьютер в одной домашней сети без изоляции клиентов и блокировки mDNS. Компьютер может быть подключён кабелем, а телефон по Wi-Fi, если роутер соединяет их в одну локальную сеть.

В проверенном окружении используются .NET SDK 8.0.426 x64, Android Studio, JDK 17.0.12, Android SDK 36 и Gradle Wrapper 8.13. .NET SDK установлен по разрешению пользователя. Docker Desktop использует Linux-контейнеры; сборка WPF выполняется установленным Windows SDK, поэтому Dockerfile не нужен.

## Сборка Windows

В PowerShell из корня репозитория:

```powershell
dotnet restore .\windows\PCRemote.Windows\PCRemote.Windows.csproj
dotnet publish .\windows\PCRemote.Windows\PCRemote.Windows.csproj -c Release -r win-x64 --self-contained false -o .\artifacts\windows
```

Запустите `artifacts\windows\PCRemote.exe` из папки публикации вместе с остальными файлами. Это оконное приложение без консоли. **Автозапуск по умолчанию выключен**: включите галочку «Запускать при входе в Windows» в настройках, когда это потребуется. Она записывает команду только для текущего пользователя и не требует прав администратора. Обычный запуск открывает окно; запуск через автозагрузку с `--background` оставляет приложение в трее.

### Windows Firewall

При первом запросе Windows Defender Firewall разрешите доступ только для частных сетей. Если запрос не появился, откройте PowerShell от имени администратора и укажите фактический путь опубликованного EXE:

```powershell
New-NetFirewallRule -DisplayName "PC Remote (Private)" -Direction Inbound -Program "D:\path\to\PCRemote.exe" -Action Allow -Profile Private -Protocol TCP -LocalPort 49821
New-NetFirewallRule -DisplayName "PC Remote mDNS (Private)" -Direction Inbound -Program "D:\path\to\PCRemote.exe" -Action Allow -Profile Private -Protocol UDP -LocalPort 5353
```

Администратор нужен только для создания правила Firewall, не для обычного запуска PC Remote. Не создавайте правило для Public profile и не настраивайте проброс порта на роутере.

## Сборка Android

Проект содержит Gradle Wrapper. При необходимости создайте `android/local.properties` со строкой `sdk.dir=C\:\\путь\\к\\Android\\Sdk`, затем выполните:

```powershell
cd .\android
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
.\gradlew.bat :app:assembleDebug
```

Debug APK появится в `android/app/build/outputs/apk/debug/app-debug.apk`. Для установки через ADB:

```powershell
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

QR-сканер включён в APK и не требует загрузки модели при первом запуске. Камера используется только во время сканирования.

## Первый запуск и сопряжение

1. Запустите Windows-приложение и при необходимости разрешите частную сеть в Firewall.
2. Откройте раздел «Устройства» и нажмите «Добавить телефон».
3. На телефоне нажмите «Сканировать QR-код» и разрешите доступ к камере.
4. Отсканируйте код в течение трёх минут. Телефон найдёт ПК через mDNS и проверит отпечаток TLS-сертификата из QR-кода.
5. После сопряжения токен сохраняется ключом Android Keystore, а Windows-данные — с защитой DPAPI.

Для отзыва откройте «Устройства» на ПК и нажмите «Отвязать». Следующий запрос телефона получит отказ, после чего Android вернётся к экрану подключения.

## Использование

- На главном экране Android доступны блокировка сеанса, перезагрузка и выключение с отдельными подтверждениями.
- На вкладке «Компьютеры» можно подключить несколько Windows-компьютеров отдельными QR-кодами и переключаться между ними. Прежняя одиночная привязка переносится автоматически при запуске новой версии.
- Список приложений загружается только при открытии экрана, вручную по кнопке обновления и после выхода или завершения. В него входят приложения с видимыми окнами и действующим значком в трее. Скрытые фоновые окна и старые записи о значках не добавляются. Значки с нестандартными идентификаторами на старых версиях Windows без NotifyIconSettings могут не определяться.
- «Выйти» сначала отправляет приложению обычный запрос на закрытие, чтобы оно могло сохранить данные. «Завершить принудительно» останавливает дерево процессов; приложение или его отдельная служба всё равно могут запустить его снова.
- «Завершить все принудительно» затрагивает только разрешённые пользовательские приложения текущего сеанса. Системные процессы, оболочка Windows и PC Remote исключаются на стороне ПК.
- Крестик Windows-окна скрывает его; сервер продолжает работать. Полный выход выполняется через меню значка в трее.

## Типичные проблемы

- **ПК не найден:** проверьте одну локальную сеть, Private network profile Windows, разрешение Firewall и отсутствие client isolation/guest Wi-Fi. Обход блокировки mDNS не реализуется.
- **Соединение закрывается при сопряжении:** кабель на ПК и Wi-Fi на телефоне допустимы, если оба получили адреса одной локальной сети (например, `192.168.1.x`). Проверьте, что PC Remote запущен, Firewall разрешает ему частную сеть, а Wi-Fi не гостевой и не изолирован от Ethernet. После ошибки можно повторно отсканировать тот же QR-код, пока он не истёк.
- **Ошибка идентичности:** удалите сохранённую привязку на телефоне/ПК и создайте новую; не обходите проверку сертификата.
- **Доступ отозван:** снова выполните сопряжение с новым QR-кодом.
- **Приложение не закрывается:** оно может быть запущено с повышенными правами, защищено Windows либо его процессы нельзя безопасно связать. PC Remote намеренно откажется от рискованного завершения.
- **Windows-проект не собирается:** нужен .NET 8 SDK на Windows. Linux-контейнер Docker не поддерживает WPF.

## Проверки

Из корня репозитория: `dotnet run --project tests/PCRemote.Checks`. Тест использует временное DPAPI-хранилище и свободный HTTPS-порт. Он проверяет TLS pinning, авторизацию, одноразовый pairing, отзыв токена, дедупликацию запросов, группировку, обычный выход и принудительное завершение специально созданных тестовых окон. Реальные приложения, блокировка и выключение не затрагиваются.

Для повторения Android→Windows проверки запустите эмулятор и выполните `./tests/Test-Android.ps1`. Параметры `-SdkPath`, `-JdkPath`, `-Device` позволяют указать существующие инструменты и ADB serial эмулятора. Скрипт собирает и устанавливает оба APK, запускает временный сервер и `IntegrationTest.kt`, затем завершает только созданный им тестовый процесс. В эмуляторе используется адрес хоста `10.0.2.2`; синтетические Android-данные очищаются. Логи проверок остаются в игнорируемом `artifacts/`.

Фактически проверены Windows Release-сборка, запуск WPF, отсутствие автоматической записи автозапуска, второй экземпляр, HTTPS и безопасные интеграционные проверки. На эмуляторе проверены Android → Windows HTTPS, pairing без камеры, отказ неверным pin/token, Keystore и запуск Activity. mDNS в домашней сети, QR через камеру телефона, переключение нескольких ПК, трей/автозапуск после входа и реальные блокировка/перезагрузка/выключение остаются для ручной проверки пользователем; опасные системные команды в проверках не запускаются.
