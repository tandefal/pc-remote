# PC Remote

PC Remote позволяет управлять Windows 10/11 x64 компьютером с Android-смартфона (Android 10+). Приложение работает в локальной сети: устройства обнаруживаются автоматически, а безопасное соединение настраивается при сопряжении.

Пока Android-приложение открыто, состояние блокировки ПК и список приложений обновляются автоматически. При сворачивании соединение закрывается, при возвращении восстанавливается с загрузкой актуальных данных. Во время первоначального подключения отображается экран «Подключение…». В разделе «Приложения» доступно только принудительное завершение с подтверждением; кнопки ручного обновления нет.

В разделе «Компьютеры» кнопка корзины удаляет сопряжение с телефона, даже если ПК недоступен. Для повторного подключения отсканируйте новый QR-код. Чтобы также удалить запись телефона на ПК, откройте раздел «Устройства» в Windows-приложении.

## Установка

Скачайте актуальные файлы со страницы [Releases](https://github.com/tandefal/pc-remote/releases):

- **Windows:** `PCRemote-Windows-X.Y.Z-Setup.exe`. Запустите установщик и выберите папку установки. Права администратора не нужны.
- **Android:** `PCRemote-Android-X.Y.Z.apk`. Откройте APK и подтвердите установку, если Android запросит разрешение на установку из этого источника.

Для работы устройств в одной локальной сети разрешите PC Remote доступ через брандмауэр Windows для частных сетей.

## Сборка

### Windows

Нужен Windows и .NET 8 SDK. Из корня репозитория выполните:

```powershell
dotnet publish windows\PCRemote.Windows\PCRemote.Windows.csproj -c Release -r win-x64 --self-contained true -o artifacts\windows
```

Чтобы собрать установщик, потребуется Inno Setup 6. Сборка установщика и Android release APK выполняется скриптом релиза.

### Android

Нужны JDK 17 и Android SDK. При необходимости укажите путь к SDK в `android/local.properties` через `sdk.dir`. Затем выполните:

```powershell
cd android
.\gradlew.bat :app:assembleDebug
```

APK будет создан в `android/app/build/outputs/apk/debug/app-debug.apk`.

### Полный релиз

Для Windows установщика и подписанного Android APK нужны Inno Setup 6 и постоянный ключ подписи Android. Первый релиз:

```powershell
.\packaging\Build-Release.ps1 -Version 1.0.0 -VersionCode 1 -InitializeSigningKey
```

Последующие релизы собирайте с тем же ключом, увеличивая версию и `VersionCode`:

```powershell
.\packaging\Build-Release.ps1 -Version 1.0.1 -VersionCode 2
```

Файлы релиза и контрольные суммы появятся в `artifacts/release/`.

Для выпуска одной платформы добавьте `-Platform Android` или `-Platform Windows` (по умолчанию `All`). Например, изменения только Android:

```powershell
.\packaging\Build-Release.ps1 -Platform Android -Version 1.0.5 -VersionCode 6
```

В релиз загружайте только файлы выбранных платформ и созданный файл контрольных сумм. Повышайте версии последовательно; Android также требует увеличения `VersionCode`. Проверка обновлений ищет последний стабильный релиз с файлом своей платформы и сравнивает версию в имени файла, пропуская релизы другой платформы. Номер общего тега не заставляет обновлять обе программы. Windows-релиз не требует Android-ключа, Android-релиз — Inno Setup.

Для перехода со старой проверки сначала выпустите обе программы с новой логикой. После установки этого переходного обновления можно публиковать платформы отдельно.



При ошибке чтения или расшифровки настроек исходное хранилище сохраняется. Windows останавливает запуск с сообщением; Android показывает ошибку, последующая запись сопряжений требует успешного чтения. Перед ручным восстановлением закройте приложение и сохраните копию зашифрованного файла. Утрата DPAPI-профиля или ключа Android Keystore не позволяет восстановить секреты из одного файла.

CI (`.github/workflows/checks.yml`) собирает Windows и Android, выполняет безопасные проверки хранилища/адресной политики и Android lint. Локально: `dotnet run --project tests/PCRemote.Checks -c Release -- --storage-only`; полный набор без этого параметра создаёт и закрывает только тестовые окна. Физические сети, VPN и сопряжение камерой требуют отдельной проверки.

Штатный выход проверяется по процессам: сворачивание окна в трей не считается завершением. Принудительная команда завершает только проверенные процессы выбранного приложения. Обнаруженный повторный запуск сообщается пользователю.

Публикация релиза допускается только после успешного CI для выпускаемого коммита и успешной локальной релизной сборки. Android CI явно устанавливает platform-tools, платформу API 36 и build-tools 36.0.0 без устаревшего пакета tools.
